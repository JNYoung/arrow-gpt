# Arrow Again 设计推进文档

日期：2026-05-30

## 目标效果

Arrow Again 的验证目标是「方向方块飞出棋盘」，而不是抽象圆形棋子。玩家应该在 3 秒内理解：

- 方块上的箭头代表离场方向。
- 前方无遮挡的方块可以飞出。
- 被挡住的方块会反馈错误并消耗生命。
- 清空棋盘即可过关。

视觉关键词：清爽网格、玩具方块、高对比箭头、黄色可行动提示、红色阻塞反馈。

## 当前差异与已收敛方向

| 问题 | 影响 | 处理方向 |
| --- | --- | --- |
| 棋子是圆形徽章感 | 和 Tap Away / Arrow Escape 用户预期不一致 | 改成圆角方向方块，按方向使用不同色，当前可射方块用黄色高亮 |
| 关卡只有 10 关 | 无法做留存和广告点位节奏验证 | 扩展到 100 关，按 easy / medium / hard / boss 编排 |
| 关卡数据重复维护 | 真实运行关卡和校验副本会漂移 | 改为 `src/game/levels.json` 单一数据源 |
| 只有数据校验 | 无法发现页面、交互、弹窗、移动端回归 | 增加 Playwright E2E 脚本和关卡平衡性脚本 |
| 广告点位停留在设计层 | 无法验证玩家是否能进入提示 / 复活闭环 | 增加平台无关 rewarded ad mock，覆盖提示和复活 |

## 关卡节奏

| 区间 | 作用 |
| --- | --- |
| 1-5 | 新手理解方向、阻挡、提示、边缘优先 |
| 6 | 第一道 Hard 门槛，验证弹窗和耐心关 |
| 7-14 | 缓冲 + 中等形状题，训练横竖链条 |
| 15 | 第二道 Hard，开始验证可选数更低的局面 |
| 16-40 | 中段关卡池，适合素材录制和 A/B 难度 |
| 41-80 | 长线递增段，逐步提升密度、阻塞率和低分支步数 |
| 81-100 | 终局 Hard / Boss，用于高留存用户和长线内容感 |

## MVP 指标

| 指标 | 可接受线 |
| --- | ---: |
| 新手 1 分钟完成率 | 80% |
| 前 5 关完成率 | 60% |
| 第 6 关进入率 | 35% |
| 提示按钮点击率 | 20%-45% |
| D1 留存 | 30% |
| 人均激励视频机会 | 1.2+ |

## 广告点位预留

当前版本先不接真实广告 SDK，但 UI/玩法已经适合以下点位：

| 场景 | 形式 | 奖励 |
| --- | --- | --- |
| 卡关后 | 激励视频 | 高亮 3 个可射方块 |
| 生命耗尽 | 激励视频 | 复活并恢复 1 点生命 |
| Boss 关失败 | 激励视频 | 保留当前棋盘继续 |
| 每 3-5 关通关后 | 插屏 | 只在结算后触发 |

## E2E 回归范围

`npm run e2e` 覆盖：

- 首屏可见。
- 点击开始进入第一关。
- 错点阻塞箭头会出现错误反馈。
- 提示按钮通过 rewarded ad mock 高亮可行动箭头。
- 生命耗尽后通过 rewarded ad mock 复活并继续当前棋盘。
- 第一关完整通关并显示结果。
- 关卡选择能访问完整 100 关包。
- 解锁状态下进入 Hard 关会出现确认弹窗。
- 移动端和桌面宽度都能渲染首屏。

`npm run verify:balance` 覆盖：

- 100 关数量和顺序。
- 每关唯一坐标、边界合法、可完成。
- 目标步数与棋子数平衡。
- easy / medium / hard / boss 标签与计算得分匹配。
- 相邻关卡得分不出现离谱尖峰或断崖式回落。
- 每 10 关章节平均难度不能明显倒退。

后续应补充：

- 低端 Android WebView 性能和触控延迟。
- 微信 / 抖音 / Meta Instant Games 平台适配层的 smoke test。
