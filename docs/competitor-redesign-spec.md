# Arrow Again 竞品级重设计规格

日期：2026-05-30  
概念图：`docs/assets/arrow-maze-competitor-concept.png`

## 设计判断

当前版本的问题不是功能缺失，而是视觉语义还停在「网格 demo」。竞品态需要让用户第一眼看到：

- 这是一个复杂路径逃脱谜题，不只是点格子。
- 箭头有明确路线、阻塞、出口门和逃逸方向。
- 棋盘本身有可录素材价值：路径亮起、出口释放、失败阻塞都能成为短视频钩子。

## 新视觉锚点

采用「SVG 迷宫管道 + 箭头滑块」作为主视觉。

| 层级 | 设计要求 |
| --- | --- |
| 背景 | 冷白 / 极浅蓝灰，减少装饰，突出棋盘 |
| 棋盘 | 大面积圆角板，像磨砂玻璃 / 搪瓷轨道盘 |
| 路径 | SVG 圆角管道，带白色厚轨、彩色内芯、轻微 glow |
| 出口 | 棋盘边缘有颜色闸门和方向标识 |
| 箭头 | 圆角矩形滑块，粗箭头图标，方向色但可移动时统一黄色高亮 |
| HUD | 极简：关卡、生命、步数、金币，不抢棋盘视觉 |
| 底部工具 | 图标化：提示、撤销、洗牌 / 复活，广告奖励可挂角标 |

## 本轮实现范围

先做视觉架构重构，不立刻改核心规则：

1. 保留当前 `row / col / dir` 关卡数据和直线逃逸规则。
2. 棋盘背景从 Canvas 网格降级为柔和面板。
3. 新增 SVG 迷宫层，基于每个箭头生成可视路径、出口门和高亮路径。
4. 后续如数据验证表现好，再把规则从「直线出界」升级为「沿路径图逃逸」。

## 为什么暂不直接重写规则

直接改成路径图规则会影响：

- 关卡数据结构：需要 nodes / edges / gates。
- 可解性校验：从直线阻挡变成图遍历和占位冲突。
- 动画：箭头不再直线飞出，而是沿 SVG path 运动。
- E2E：通关路径和失败路径都要重写。

更稳的路线是先把「看起来像路径谜题」做出来，同时保留已有 30 关和 E2E，然后逐步迁移。

## 下一阶段规则数据草案

```ts
interface MazeNode {
  id: string;
  row: number;
  col: number;
}

interface MazeEdge {
  from: string;
  to: string;
  path: string;
}

interface MazeGate {
  id: string;
  node: string;
  dir: Direction;
}

interface MazePiece {
  id: string;
  node: string;
  dir: Direction;
}
```

## 成功标准

- 首屏截图不再像原型网格。
- 棋盘有明显复杂迷宫路径。
- 可行动箭头和其出口路径一眼可读。
- 移动端 390x844 不拥挤，底部工具不遮挡棋盘。
- E2E 仍覆盖 rewarded hint / revive / hard modal / 100 关。
